# Implementation Plan: auth-session-cleanup

Spec: [`SPEC-auth-session-cleanup.md`](SPEC-auth-session-cleanup.md) (approved 2026-10-11). Issue #178.

## Overview

A general retention runner, started one minute after the API listens and every 24 hours after that, runs purge jobs. The first job deletes `auth_sessions` rows that ended more than 180 days ago. There is no migration and no new infrastructure. The branch lives in its own worktree, because another session is working on `feat/sysadmin-alerts` in the main checkout. Both branches touch `src/index.ts`, so this one is rebased onto `dev` after that one merges.

## Architecture Decisions

- **Policy in `lib/retentionPolicy.ts`:** constants plus the pure `authSessionCleanupCutoffs(now)`. The job and the database test share it.
- **Delete in `authRepository`:** `deleteEndedAuthSessions({ cutoff, idleCutoff, batch })` deletes one batch through the Prisma client (`findMany` ids + `deleteMany`) and returns the count.
- **Scheduling in `lib/retention.ts`:** a list of jobs (`name`, `purgeBatch(batch) → count`). It owns the timers, the batch loop and cap, and the logging. It takes its clock and timers as injectable dependencies, so tests need neither a database nor real time.
